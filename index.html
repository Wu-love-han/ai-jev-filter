为什么是「对话」而不是「画布」？

画布适合“我已经知道流程长什么样”的人。新手更需要先把框架意识长出来：需求 → 检索 → 判断 → 排序 → 摘要。这一版把框架藏在对话背后，你只需要提问，但每一步都会展开给你看。

JEV 是什么？

JEV（TypeSafe System One）是一类“判断模型”：它不写文章，只回答一个被类型化的问题，返回概率或分数。三种原语：

  • noul — 是 / 否，返回 0-1 概率（这条信息是真的吗？）
  • score — 打分，返回 2-10 分（这条有多符合需求？）
  • choice — 单选，返回一个分类（这属于教程还是代码库？）

所以写提示词时要写类型化问题，不要写“帮我分析一下”。这是本工作台反复演示的第一条工程习惯。

一次调用，问三个问题

官方 JEV 的形状是：state + 一组问题，**同一请求内并行**返回答案。所以本工作台对每条信息只发一次请求，同时问「真伪 / 匹配度 / 分类」，而不是发三次。加问题几乎不增加响应时间，但每多一条信息就多一次调用。

判定引擎可以换

  • 本地启发式 —— 离线、确定性，用来把流程跑通
  • 浏览器 ONNX —— 移植 local-jev：用 NLI 模型在本机真推理，零 Key、数据不出浏览器
  • 本地开源服务 / 官方 API —— ollaya（wire-identical 于 TypeSafe）或官方云端，经本地代理，Key 只在服务端

切换后端不改流水线；真实后端挂了会自动回落启发式，并在界面上写清楚原因。

判断与生成要分开

先让 JEV 把噪音筛掉，再让大模型写摘要 —— 顺序反了就是“又当裁判又当选手”，既贵又不可审计。界面上每一步的耗时和判定分布都能展开看。

阈值写在代码里

模型只给概率，“过不过”由阈值决定。阈值是你能调的旋钮：调高更严格，调低更宽松。可复现、可解释。

脱敏不是可选项

手机号、身份证、邮箱、微信号在进入模型之前就被本地规则屏蔽。每次检索都会告诉你屏蔽了几处 —— 这就是合规的最小实践。

三步练手建议

  1. 先点右侧「新手入门」里的模板，看完整条链路怎么跑。
  2. 把需求改得更具体，观察匹配分怎么变。
  3. 到「检索设置」里把阈值调到 0.8，再跑一次，看结果少掉多少。
